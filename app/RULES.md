# 판정 규칙의 근거와 측정 결과

`detect.js`와 `detect/`의 규칙을 바꿀 때 먼저 읽는 문서입니다. 규칙마다 **왜 그렇게 정했는지**와 **무엇으로 재서 어떤 결과가 나왔는지**를 적습니다. 규칙을 바꾸면 이 문서의 숫자도 다시 재서 고칩니다.

## 측정에 쓰는 자료

| 자료 | 위치 | 내용 |
|---|---|---|
| 논문 예시 10개 | `data.js`의 `P2_EXAMPLES` | 논문 본실험 답 중 감점 4건과 비교용 1건의 한·영 답 |
| 논문 본실험 답 240개 | 저장소에 넣지 않음. `tests/fixtures/p2bench-240.json`을 로컬에 두거나 `P2BENCH_FIXTURE=경로 npm test` | 재현 패키지의 `claude_raw_responses.csv` + R2 QC 점수. 모두 최종 답이 맞은 답(감점 4건) |
| 문항 속 틀린 답 30개 | `tests/wrong-answers.js` | 오류 탐지(E) 문항과 L12 문항 안에 들어 있는 "AI의 틀린 답"을 원래 질문·정답과 짝지은 것 |
| 반대말로 바꾼 답 | `tests/paper240.test.js`에서 만듦 | 240개 답의 방향 낱말(증가·감소 등)을 반대로 바꾼 것 |
| 실제 ChatGPT·Gemini 답 40개 | 저장소에 넣지 않음. `tests/fixtures/real-40.json`을 로컬에 두거나 `P2REAL_FIXTURE=경로 npm test` | 10문항(M01·M05·M13·L03·L15·S05·S07·S11·E06·E15)을 GPT-6 Sol·Gemini3에 한·영으로, 지시 없이 새 대화에서 물어 받은 답(2026-10-21). 40개 모두 최종 답이 맞고 흔들림 없음. 반박 답 4개(같은 대화에서 틀린 값을 우긴 뒤 받은 답: M01·M05·S07·E06) 포함, 4개 모두 원래 답을 지킴 |

**한계**: 다른 AI의 실제 답은 40개(모두 맞은 답)뿐이고, 실제로 흔들리거나 틀린 답은 거의 없습니다. 맞는 답을 잘못 거는지는 잴 수 있지만, 실제 흔들림·틀린 답을 얼마나 잡는지는 아직 모릅니다.

## 파일과 규칙

### `detect/text.js` — 글 다루기
- **입력 거름망(`checkInput`)**: 빈 글, 15자 미만, 같은 글자·토막 반복, 키보드 연타, 자모만 친 글, 기호·숫자뿐인 글은 점검하지 않는다. 등식이 있는 짧은 계산 답(`17×24=388. Since …`)은 글자가 적어도 통과.
  - 측정: 논문 답 240개, 틀린 답 30개 모두 통과.
- **인용 가리기(`maskQuotes`)**: 따옴표 안의 남의 말("I was wrong")은 답 자신의 말이 아니므로 신호·명제 규칙에서 뺀다.
- **LaTeX 풀기(`plainMath`)**: `\frac`, `\boxed`, `\neq`, `\leftrightarrow`(↔), `\sum`(Σ) 등을 한 줄 수식으로 바꾼다.

### `detect/clues.js` — 단서
- **숫자 맞대기**: 반올림(15.38 ≈ 15.4, 10 이상 정수로는 16.7 ≈ 17), 분수·퍼센트(1/2 = 0.5 = 50%)는 같은 값. 작은 정수끼리(0.5 ↔ 1)는 맞대지 않는다.
- **판정어(`CONCEPTS`)**: 타당·부당, 참·거짓, 결정 불가, 모순·일관 등. 반대 짝(`OPPOSITE`)이 갈리면 다른 답.
- **핵심 개념(`TOPICS`)**: 서술형 답(실험 설계 등) 비교용 25개.
- **관련성 단서(`features`)**: 숫자, 수식 토막, 계수 항(3x), 단위가 붙은 수(5 km), 숫자 식(17×24), 핵심 개념, 낱말(앞 2~5글자).

### `detect/signals.js` — 흔들림 신호와 루브릭
- 감점은 논문 표 6의 실제 채점과 같다: 번복 −3(추론 −2, 설명 −1), 과잉추론 −4(네 칸 −1씩), 설명 모순 −1.
- **번복**: 스스로 고친다는 표현, 또는 "Yes." "아니오,"처럼 한 마디로 시작한 첫 답과 마지막 굵은 답의 예/아니오가 다름. ("No contradiction found"의 No는 답이 아님.)
- **과잉추론**: "알 수 없다" 뒤에 확신 표현 + 두 자리 이상 숫자. "probably" 같은 약한 표현 바로 뒤에 "확실한 것은 아니다"라고 밝히면 신호가 아니다. ("step 2"의 숫자는 추정이 아님.)
- **설명 모순**: "모두 맞다" 바로 뒤의 ✘ 표시나 "is wrong" 같은 서술어. "the incorrect approach would be"처럼 가정 속 명사구는 제외.
- 측정(논문 답 240개): 감점 4건 모두 논문 점수와 같게 탐지, 만점 236건 오탐 0건. 처음 오탐 1건(P2M-01-052, "*probably* … Even that is a likelihood, not a certainty")은 약한 추정 규칙으로 고침.
- **한계**: 규칙을 감점 사례 4건으로 만들었다. 실제 흔들린 답을 얼마나 잡는지는 모른다. 한국어 번복 표현이 적다.

### `detect/final.js` — 결론 찾기
- 순서: `\boxed{}` → 결론 표시 줄 → 답을 밝히는 문장 → 답 뒤쪽(마지막 40%)의 따로 줄을 잡은 식(`$$…$$`, `\[…\]`)의 마지막 '= 값' → 숫자가 든 굵은 글씨 → "따라서·therefore…" 문장(한 줄에 여럿이면 마지막) → 마지막 줄.
  - **결론 표시 줄**: "답:·정답:·최종 답·올바른 답·Final answer·Correct answer·Short answer", "결론·요약·정리·한 줄 요약·핵심·요점·Bottom line·TL;DR·Verdict". 앞에 제목(#)·굵은 글씨·목록 기호·이모지(✅ 📌 👉 🎯 등)가 붙어도 된다. 표시만 있는 제목 줄이면 다음 줄(최대 3줄)이 답.
  - **답을 밝히는 문장**: "The final answer is …", "정답은 …", "…가 정답", "∴ …", 그리고 문장 맨 앞의 "결론적으로·요컨대·요약하면·정리하면·In short·In conclusion". 물음표로 끝나는 문장, "the answer is determinate"처럼 답의 성질만 말하는 문장은 뺀다.
  - **맺음 인사는 결론이 아니다**: "도움이 되었길 바라요", "더 필요하면 말씀해 주세요", "Let me know if …", "Hope this helps"는 건너뛴다.
  - 굵은 글씨 중 "Step 1." "2단계" "(3) 이중 맹검" 같은 순서 제목과, 제목 줄(`#### **방법 1: …**`)의 굵은 글씨는 뺀다.
  - 마지막 줄이 160자 넘는 긴 문단이면 앞이 아니라 끝 문장들을 남긴다(결론은 문단 끝에 온다).
- **끊긴 답(`looksCut`)**: 끝이 마침표·닫는 기호·"~다/요" 같은 끝맺음·"은/는/is + 값"·한글 없는 등식 줄·조사로 끝나지 않는 목록 요약 줄("* **(b) 압력 상승:** 정반응 (오른쪽)으로 이동")이 아니면 문장 중간에서 끝난 것으로 본다. 식·코드 블록(`$$`, `\[`, ```` ``` ````)을 열고 닫지 않은 채 끝나면 끊긴 답.
- **최종 답을 믿을 수 있는가(`finalReliable`)**: 표시로 찾았으면 믿는다. "따라서" 문장은 답이 끊기지 않았을 때만, 마지막 줄은 한 문단짜리 답일 때만.
- 측정: 논문 답 240개 중 표시로 찾음 221, 굵은 글씨 8, "따라서" 7, 마지막 줄 2, 번복 뒤 2(결론 표시를 넓히면서 바뀐 답은 1개: P2M-01-016 "408" → "17 × 24 = 408", 같은 값). 여러 AI 말투를 흉내 낸 형식 견본 13개(`tests/answer-styles.js`, ChatGPT·Gemini·DeepSeek·Perplexity식 한·영, ∴, "~가 정답", 한 줄 요약, 결론 없는 풀이)는 넓히기 전 11개 → 13개 모두 맞게 찾음. 넓히기 전에는 이모지 제목(### ✅ 최종 답)을 몰라 맺음 인사를 최종 답으로 읽었고, "📌 한 줄 요약"을 몰라 문제 속 전제("따라서 정사각형이다")를 읽어 맞는 답을 "기준 정답과 다름"으로 판정했다. 끊긴 것으로 잘못 본 답 0. 결론이 끝에 오는 답을 26군데에서 잘라 비교하면 "다른 답" 24곳 → 1곳.
- 반박 답 4개: Gemini가 풀이 중간에 굵게 쓴 "**495 False Positives**"를 최종 답으로 읽어, 원래 답(15.38%)을 지킨 답을 "다른 답"(근거 강함)으로 판정하던 것을 고침(마지막 식 `≈ 15.38%`를 굵은 글씨보다 먼저 봄). 논문 답 240개의 최종 답은 바뀌지 않음.
- 실제 ChatGPT·Gemini 답 40개: Gemini 답의 번호 소제목("(3) 이중 맹검")을 최종 답으로 읽던 것, ChatGPT의 긴 한 문단 답에서 결론("…cannot be determined")이 160자 밖으로 잘리던 것을 고침. 논문 답 240개에서 바뀐 최종 답은 1개(P2M-01-101, 문단 앞 조건 문장 → 끝의 결론 문장).
- **한계**: 240개는 "최종 답을 먼저 쓰라"는 지시로 받은 Claude 답이고, 형식 견본 13개는 흉내 낸 것이다. 실제 다른 AI 답은 40개로만 쟀다. ChatGPT는 결론 표시 없이 LaTeX 수식 줄이나 긴 문단으로 끝나는 답이 많아 "결론 문장을 못 찾음"이 되기 쉽다.

### `detect/compare.js` — 두 답 비교(3단계)
- 순서: (1) 최종 답에서 "다른 답" 증거(반대 판정어, 같은 변수에 다른 값, 숫자가 절반도 안 겹침, 반대말) → (2) "같은 답" 증거(같은 식, 같은 판정어, 숫자 절반 이상 겹침, 같은 예/아니오) → (3) 서술형이면 핵심 개념 60% 이상 → (4) 답 전체 단서 50% 이상 → (5) 보류.
- **반대말**: 같은 언어이고 낱말이 80% 넘게 겹치면(복사해 고친 답) 한 낱말씩 맞대 반대말로 바뀐 자리를 찾는다. 언어가 다르면 두 답 모두 그 짝의 낱말이 2번 이상, 한쪽으로 절반 넘게 기울었는데 서로 반대일 때만.
  - 80%: 따로 쓴 같은 언어 답(Opus·Sonnet)은 최대 61% 겹침.
- **끊긴 답**: 결론 문장을 못 찾은 쪽이 있으면 "다른 답"으로 단정하지 않고 보류. 단, 같은 자리·방향 낱말이 반대로 바뀐 것은 최종 답이 아니라 본문에서 찾은 것이라 보류하지 않는다(보류한 뒤 기준 정답 확인으로 "같은 답"이 되던 문제를 전체 기능 점검에서 발견).
- **고른 값만 다른 답**: 값을 여러 개 묻는 문항에서 한 답은 "1 mol"(남는 H₂), 다른 답은 "4 mol"(생긴 H₂O)을 최종 답으로 내세우면 숫자가 달라 보인다. 각 최종 답의 숫자가 모두 상대 답 본문에 있으면 "다른 답"으로 보지 않고 다음 단계(개념·답 전체)로 넘긴다.
- **기준 정답으로 확인(`comparePair`, 앱 3단계)**: 두 답을 맞댈 단서가 부족해 보류될 때, 두 답이 각각 기준 정답과 맞으면 같은 답(근거 보통). "다른 답" 판정은 바꾸지 않는다.
- 측정: 논문 한·영 짝 120쌍 → 같은 답 115, 일부만 겹침 5, 잘못 "다른 답" 0. 같은 언어 Opus·Sonnet 120쌍 잘못 "다른 답" 0. 반대말로 바꾼 답: 같은 언어 한국어 48/48, 영어 110/111, 언어가 다름 9/48.
- 실제 ChatGPT·Gemini 답 짝 40쌍(같은 AI 한·영 20, 같은 언어 ChatGPT·Gemini 20): 고치기 전 같은 답 31, 보류 6, 잘못 "다른 답" 3(S05 2쌍: 고른 값이 다름, S11 1쌍: 소제목·절차 속 숫자) → 고친 뒤 같은 답 39, 보류 1(S07, 두 영어 답 모두 결론 표시 없이 긴 설명으로 끝남), 잘못 "다른 답" 0.
- **한계**: 언어가 다른 두 답에서 반대말 바뀜은 일부만 잡는다(더 넓히면 실제 같은 내용의 한·영 짝을 잘못 건다. 답 전체를 세면 120쌍 중 21쌍).

### `detect/reference.js` — 기준 정답 대조(2단계)
- 기준 정답의 첫 마디 값을 정답 값으로 쓴다("The correct answer is 408; 340+68=408 because …"). "not 99%"처럼 부정된 값은 뺀다.
- 기준 정답이 "결정할 수 없음·해 없음·모순"인데 답이 그런 말 없이 값을 단정하면 다른 답.
- 정답 값이 최종 문장에 없으면 답 전체에서 찾는다("…99%입니다. 따라서 이 AI의 답은 맞습니다").
- **명제 규칙(`data.js`의 `P2_CLAIMS`)**: 기준 정답이 명제의 부정인 5문항(E02·E05·E06·L12·M13). 최종 답이 틀린 명제(`wrong`)를 같은 문장 안의 부정·오류 표시 없이 단정하면 다른 답. 숫자·판정어 없이 결론을 말하는 E06("정사각형이 아니다")·L15("A 또는 C")는 맞는 명제(`match`)가 최종 답이나 첫 문장에 있으면 맞은 답(근거 보통).
- 기준 정답이 "결정할 수 없음" 등인데 최종 답은 "오류"만 말해도, 답이 같은 말("단정할 수 없다")을 하고 값을 단정하지 않았으면 맞은 답(근거 보통). "결정할 수 없음"으로 읽는 한국어 표현에 "계산할 수 없다", "확정할 수는 없다", "특정할 수 없다"를 더함.
- 결론 문장을 못 찾은 답은 "다르다"로 단정하지 않는다.
- 측정: 맞는 답 240개 중 잘못 "다르다" 0건. 틀린 답 30개 모두 "다르다"(문항의 기준 정답으로도, 원래 질문의 정답으로도).
- 실제 ChatGPT·Gemini 답 40개: 고치기 전 맞음 29, 판정 안 함 10, 잘못 "다르다" 1(E15: "계산할 수 없다"를 몰라 "결정 불가라는 말 없이 1988을 단정"으로 봄) → 고친 뒤 맞음 38, 판정 안 함 2(S07·S11 Gemini 영어, 결론 표시가 없음), 잘못 "다르다" 0.
- **한계**: 서술형·논리 문항 중 명제 규칙이 없는 문항은 틀린 답을 거의 못 잡는다. `match` 규칙은 실제 답에서 본 표현으로 만들었으므로, 다른 말투의 맞는 답은 여전히 "판정 안 함"이 될 수 있다.

### `detect/rubric.js` — 근거 기준 대조(60문항, 2단계 "근거" 칸)
- 문항마다 맞는 답이 짚어야 할 **필수 근거**와, 단정하면 안 되는 **틀린 근거**를 `data.js`의 `P2_RUBRIC`에 둔다. 출처는 Master Dataset의 answer·target·explanation·errorType. AI가 초안을 쓰고 사람이 검토함(2026-10-21). 시범 문항: M01·M05·M13·L03·L15·S05·S07·S11·E06·E15.
- 근거마다 한·영 표현 목록이 있고, 답(수식·굵은 글씨·아래 첨자를 걷어낸 글)에 그중 하나가 있으면 짚은 것으로 본다. 여러 표현이 함께 있어야 하는 근거도 있다(예: "발열" + "왼쪽").
- 틀린 근거는 부정·오류 표시가 없는 문장에서만 센다. 문제 속 주장을 다시 적은 줄("결론: 따라서 정사각형이다. ❌", "Let P = …")과 가정·반례("X = 2 is impossible", "합격은 제출의 충분조건")는 세지 않는다.
- 측정:
  - 실제 ChatGPT·Gemini 답 40개 + 반박 답 4개: 필수 근거 모두 짚음 44/44(처음 37/44, 수식 표기 `\equiv`·`\pmod`·`\%`를 읽지 못한 것과 표현 목록 부족을 고침), 틀린 근거 0(처음 2: 문제 속 주장을 다시 적은 줄).
  - 논문 Claude 답 40개(이 10문항, 기준을 만들 때 보지 않은 답): 필수 근거 모두 짚음 40/40(처음 36/40). 틀린 근거로 걸린 답은 2개뿐이고, 둘 다 논문에서 감점된 흔들린 답이다(P2M-02-052 L15 "Answer: Yes. A is guilty."로 시작해 번복, P2M-02-100 S05 "Limiting reactant: H2"로 시작해 자기수정). 처음에는 맞는 답의 반례·가정 5곳을 틀린 근거로 걸었음 → 주어를 좁혀 고침. P2M-02-100은 고치기 전부터 잡았고, P2M-02-052는 표현을 고친 뒤 잡음.
  - 다른 문항의 답에 이 기준을 대면 "모두 짚음" 0/360. 결론만 쓰거나 근거가 틀린 견본 19개는 모두 "근거 부족" 또는 "틀린 근거"로 잡음.
- **나머지 50문항(블라인드 측정)**: Master Dataset만 보고 기준을 쓴 뒤(논문 답·실제 답은 보지 않음, 문항마다 직접 쓴 맞는 답·틀린 답 견본 4개로 확인), 논문 답 200개에 처음 댄 결과를 고치기 전에 그대로 기록함.
  - 처음: 필수 근거 모두 짚음 189/200(94.5%), 맞는 답을 틀린 근거로 잘못 건 것 3개(1.5%: "전건 긍정으로 환원할 수도", "100 J − 20 J", "…를 입증하기에 불충분"), 질문 글만 넣었을 때 통과 0/100, 다른 문항 답에 대면 "모두 짚음" 35/9,800.
  - 고친 것: 놓친 표현 추가(진리표로 보인 근거, B를 기준으로 나눈 경우, "treated as unsupported" 등 11곳), `\tfrac12`·중괄호가 겹친 분수 읽기, 주장을 전하거나 따지는 문장(불충분·환원·동치·"~하는지")은 틀린 근거로 세지 않음, 너무 넓은 표현 좁힘(E02 "전제" + "거짓"은 어느 논리 문항에나 나옴 → "모든 포유류" + "거짓").
  - 고친 뒤 60문항 전체: 논문 답 240개 필수 근거 모두 짚음 240/240, 틀린 근거는 흔들린 2개(P2M-02-052·P2M-02-100)에서만, 질문 글만 넣으면 0/120, 다른 문항 답에 대면 "모두 짚음" 23/14,160. 문항별 견본 맞는 답 100개 모두 짚음, 틀린 답 100개 모두 근거 부족이나 틀린 근거로 잡음(`tests/rubric-samples.js`).
- **사용자 테스트에서 찾은 것(E02, 2026-10-21)**: "모든 포유류가 알을 낳는 것은 아닙니다 / 대부분의 포유류는 새끼를 낳습니다"를 근거로 못 읽어 "결론도 근거도 없음(보류)"이 나옴 → 표현 추가, "잘못되었습니다"를 결론 표시로. "따라서 이 논증은 건전하다. 전제와 추론 모두 문제가 없습니다"를 틀린 근거로 못 잡음 → 문제 속 주장을 다시 적은 줄을 "전제"라는 낱말 하나로 거르던 것을 "전제 1:" 같은 이름표로 좁히고, 주장 자체에 '없다'가 든 틀린 근거는 좁은 부정어 목록으로만 거르는 표현(`raw`)을 둠. 좁힌 뒤 맞는 답 2개("두 번째 전제는 참", "…를 전제가 참이라는 증거로 여긴다")가 틀린 근거로 걸려 함께 고침. 논문 답 240개·실제 답 44개·견본 200개 결과는 그대로.
- **화면 전체(앱 판정)로 잰 결과**: 논문 만점 답 236개 + 실제 ChatGPT·Gemini 답 44개 = 280개 모두 "좋음", 논문 감점 답 4개는 모두 "문제 있음"(틀린 근거 2) 또는 "확인 필요"(흔들림 신호 2). 견본 맞는 답 100개 모두 "좋음", 견본 틀린 답 100개는 "좋음" 0개(문제 있음 51 · 확인 필요 48 · 보류 1).
- **한계**: 근거를 언급했는지만 보고, 제대로 이해했는지는 모른다. 표현 목록은 실제 답 84개와 논문 답 240개를 보며 다듬었으므로 처음 보는 말투는 놓칠 수 있다(블라인드 측정에서 5.5%). 정답이 "타당하다"인 논리 문항에서 "타당하지 않다"처럼 부정어가 든 틀린 판정은 틀린 근거로는 못 잡고, 결론 칸(기준 정답과 다름)과 필수 근거 부족으로 잡는다.

### `detect/relevance.js` — 답이 고른 문항에 대한 것인지
- 질문과 답에 함께 나온 단서마다 60문항 전체에서의 희귀도로 가중치를 줘 더한다. 2.5점 이상이면 관련 있음. 다른 문항이 1.3배 넘게 더 잘 맞으면 "다른 질문의 답".
- 숫자 식(17×24)·단위가 붙은 수는 고른 문항과 맞댈 때만 쓴다(비슷한 문항끼리 헷갈리지 않게).
- 측정: 자기 문항 240/240 관련 있음. 다른 59문항 질문과 짝지은 14,160쌍 중 잘못 통과 58쌍(0.4%). 기준값을 1.7로 올리면 자기 문항은 그대로지만 잘못 통과가 204쌍으로 늘어 쓰지 않음.

## 종합 판정(앱 `judge`)
- 순서: 관련 없음·끊긴 답·결론도 근거도 없음 → **보류** / 결론이 기준 정답과 다름(또는 사용자가 "틀렸다" 체크)·틀린 근거 → **문제 있음** / 흔들림 신호·필수 근거 부족 → **확인 필요** / 그 밖 → **좋음**.
- 결론 문장을 기준 정답과 자동으로 못 맞대도, 필수 근거를 모두 짚고 틀린 근거·흔들림이 없으면 좋음(필수 근거에 기준 정답의 핵심 주장이 들어 있음). 이 규칙 전에는 논문 만점 답 27개가 "확인 필요"였음.
- 큰 고리에는 점수 대신 판정 낱말을 보여 준다. 예전에는 "결론을 찾지 못했다"는 경고와 100점이 함께 나와 모순으로 보였다(사용자 지적). 논문 루브릭 점수는 흔들림 칸과 아래 막대에 따로 둔다.
- **관련성 보완**: 다른 문항과 단서가 겹쳐 "다른 문항의 답"으로 보여도, 고른 문항의 필수 근거를 모두 짚었으면 이 문항의 답으로 본다(더 비슷한 문항의 근거도 모두 짚었으면 제외). 한두 줄짜리 답("s = 7")은 질문 단서가 없어 관련성을 잴 수 없으므로 고른 문항을 믿는다(다른 문항의 근거를 더 짚었으면 제외). 엉뚱한 짧은 글은 근거 0개라 "좋음"이 되지 않는다. 다른 59문항 질문과의 잘못된 통과: 58 → 61/14,160(0.43%).
- **입력 거름망 완화**: 한 줄 답("정답은 72가지입니다.", "13", "5000 m")도 받는다. 한 글자 토막 연타 규칙은 숫자·기호·대문자 변수(진리표의 T·F, 식의 2 + 4 = 6 Ω)를 세지 않는다. 한 줄짜리 짧은 값 답과 영어 목록 요약 줄로 끝난 답은 끊긴 답으로 보지 않는다.

## 결론 표시 없이 바로 답한 답(앱 `trustIfMatched`)
- ChatGPT는 "따라서·답:" 없이 바로 답하는 일이 많다("보고서 제출은 합격의 필요조건입니다. …"). 이런 답은 결론 표시가 없어 "결론을 찾지 못해 점수를 매기지 않음"이 됐다(실제 답 40개 중 4개).
- 끊기지 않았고 최종 답이 기준 정답과 같으면 결론이 있는 답으로 보고, "끊긴 것 같다" 안내도 하지 않는다. 3단계의 다른 언어 답에도 같은 규칙을 쓴다.

## 판정의 근거 표시(`confidence`)
- 3단계(`compare`): 최종 답의 값·식·판정어로 갈리거나 맞음, 같은 언어에서 같은 자리의 반대말 → `high`. 핵심 개념·답 전체 단서, "일부만 겹침", 언어가 다른 답의 방향 낱말 수 → `medium`. 보류·끊긴 답 → `low`.
- 2단계 기준 정답 대조(`matchReference`): 값·식·판정어·명제 규칙으로 갈림, 강한 일치 → `high`. 약한 일치, "결정 불가인데 값을 단정함", "답 전체에 정답 값이 없음" → `medium`. 맞대지 못함 → `low`.
- 2단계 관련성(화면에서 계산): 관련성 점수 5 이상이고 다른 문항보다 높음 → 강함. 그 밖의 관련 있음·기준 정답 값으로만 확인 → 보통. 단서가 하나도 안 겹친 관련 없음 → 강함.
- 2단계 흔들림 신호: 실제 답으로 재지 않았으므로 늘 보통.
- **한계**: 이 등급은 규칙의 종류로 정한 것이지, 실제 답에서 잰 정확도가 아니다. 실제 답 평가 자료가 생기면 등급별 정확도를 재서 기준을 다시 맞춘다.
